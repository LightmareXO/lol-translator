# Tesseract.js Web相当参照条件

## 結論

Tesseract.js 5.1.1、`kor`、OEM 1、PSM 6、外部前処理なしを、既存比較と同じ28枚の字幕ROIへ適用した。
代表12字幕のCERは2.8670であり、現在のローカル原画像条件のfast 1.5567、best 1.6700より悪かった。
空白除外CERも0.8272で、ローカルfastの0.7099を下回らなかった。

したがって、Web相当条件の改善は確認できなかった。
事前条件に従い、言語指定、PSM、モデルの切り分け実験は実施していない。

## 比較条件

Tesseract.jsはNode.js上で実行したが、ブラウザ版と同じTesseract.jsパッケージ、LSTM用WASMコア、言語モデルを明示的に固定した。
ネットワークからの実行時取得やキャッシュ済みモデルの混入を避けるため、npmパッケージ内のファイルをローカルパスで指定した。

| 項目 | Web相当参照条件 | 現在のローカル条件 |
| --- | --- | --- |
| エンジン | Tesseract.js 5.1.1 | Tesseract 5.4.0.20240606 |
| 言語 | `kor` | `kor+eng` |
| OEM | 1 | 1 |
| PSM | ROI全体を6 | 1行ごとに7 |
| 2行字幕 | ROI全体を6 | 固定行帯で分割し各行を7 |
| 外部前処理 | なし | `original`、なし |
| 入力 | 抽出済みROI | 同じROIをPNG再保存したもの |

主集計は事前に固定した代表12字幕である。
隣接フレームを含む28枚は補助集計にだけ使った。
正解韓国語はAI目視転記の暫定値であり、人手確認済みでも独立評価でもない。

## 入力と対応関係の監査

次の4点を実測後に確認した。

1. Tesseract.jsへ渡した28枚とローカル`original`条件の28枚は、寸法が全件一致し、復号後の画素も28/28枚で完全一致した。最大画素差は0だった。
2. ID、group ID、動画ID、時刻、画像ファイル名、画像SHA-256、正解文、確認状態、分割、代表指定、行数を照合した。Tesseract.js 28件とローカル原画像56件に対応ずれはなかった。
3. 背景・HUDの文字化が発生した。代表12件すべてで空白除外後の予測文字数が正解文より長く、正解162文字に対して予測267文字だった。4件は不要な複数行になった。
4. 実行エラーは0件だった。`raw_output`には`recognize()`の`result.data.text`だけを保存し、例外は別の`error`欄へ保存する。エラーと認識文字列を同時に持つ記録は0件だった。

特に`g02_f02`は正解10文字に対して予測34文字、`g05_f02`は正解3文字に対して予測25文字だった。
画像を確認すると、字幕以外にミニマップ、アイコン、ゲーム背景の輪郭を含む広いROIである。
PSM 6を指定した今回の参照条件ではROI全体から字幕外の要素を大量に拾っており、その余分な出力が主CERを押し上げている。
PSMの変更だけで解消するかどうかは、改善ゲートを満たさなかったため切り分けていない。

## 実測結果

| エンジン | 原画像条件 | CER | 空白除外CER | 完全一致 | 推論中央値 |
| --- | --- | ---: | ---: | ---: | ---: |
| Tesseract.js 5.1.1 | `kor`、PSM 6、ROI全体 | 2.8670 | 0.8272 | 0/12 | 114.3 ms |
| ローカルfast | `kor+eng`、PSM 7、固定行分割 | 1.5567 | 0.7099 | 0/12 | 179.7 ms |
| ローカルbest | `kor+eng`、PSM 7、固定行分割 | 1.6700 | 0.8519 | 0/12 | 255.6 ms |

Tesseract.jsはこの環境で速かったが、精度改善にはならなかった。
28枚全体のCERは3.1599、空白除外CERは0.9500、隣接フレーム変化率は0.9375だった。

## 切り分けを行わなかった理由

切り分け開始条件は、参照条件のCERが現在のローカル原画像条件のうち最良値を下回ること、とした。
参照条件2.8670は最良ローカル条件1.5567を下回らなかったため、条件を満たさなかった。

この結果だけで、別のWeb画面で得た良好な出力を否定はできない。
そのWeb画面が画像を縮小、再切り出し、内部二値化、文字領域検出していた場合、今回指定した「外部前処理なし、同じROI」とは入力条件が異なる。
ただし、今回の指定条件については、画像取り違え、正解文の対応ずれ、エラー文混入ではなく、背景・HUD誤認を含むOCR出力そのものが悪化要因だと確認できた。
