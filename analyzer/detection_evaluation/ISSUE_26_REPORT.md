# Issue #26 連続字幕の誤統合調査

## 結論

`3ZRHyWrYBVk`の292秒付近で後続字幕が失われた原因は、検出段階の誤統合だった。

旧方式は`어 이 자식 봐라`と`기 싸움 GOAT인데?`を290.8秒から293.8秒までの一つの区間として保存していた。

区間の代表画像には290.8秒が選ばれたため、OCRと翻訳は先行字幕だけを処理していた。

最低表示時間を1.2秒から0秒へ変更しても、対象の誤統合は変わらなかった。

OCR、翻訳、再生時表示に到達する前に後続字幕の区間が存在しなくなっていたため、これらは欠落の原因ではない。

修正版は旧指標を維持し、文字内部の形を比較する別指標を追加した。

修正版では先行字幕を290.8秒から292.2秒、後続字幕を292.2秒から293.8秒として保持した。

## 再現条件

対象動画は動画ID`3ZRHyWrYBVk`、SHA-256`405E6FC63C9715D4284956DD3B41FE824410DB2C7310FE2ED1D65DA1B393F5B2`である。

動画は1920×1080、60fps、長さ553.145760秒だった。

解析範囲は285秒から300秒、走査間隔は200ms、行分割なしとした。

ROIは`x=0.019791666666666666`、`y=0.7222222222222222`、`width=0.9604166666666667`、`height=0.16666666666666666`とした。

ピクセル換算のROIは`[38, 780, 1844, 180]`である。

このROIは既存の翻訳評価データに記録された同一動画の設定から復元した。

ユーザー報告時にアプリが保存したJSONは見つからなかったため、報告時の設定との完全一致は未確認である。

動画、抽出画像、完全な解析結果JSON、個人用パスはコミットしていない。

0秒条件では289.8–290.2秒と290.2–290.8秒の短い候補が追加されたが、GOAT字幕は分離されなかった。

したがって、対象字幕は短区間として破棄されたのではない。

290.8秒の先行字幕を参照画像とした旧類似度は、同じ先行字幕のフレームで約0.95から0.98、GOAT字幕のフレームでも約0.80から0.82だった。

旧閾値0.68では、GOAT字幕を同じ字幕と判定する。

## 修正

大きな配置変化を検出する旧指標と閾値0.68は維持した。

文字内部の形を比較するため、マスクを膨張せず、上下左右1ピクセル以内の全体移動だけを許容したDice係数を追加した。

新指標は旧指標と尺度が異なるため、閾値を流用せず0.65へ設定した。

新指標だけが変化を示す場合は3フレーム連続したときに確定し、1フレームまたは2フレームの揺れでは分割しない。

200ms走査では、最初の変化候補から約0.4秒後の3枚目で確定するが、区間境界は最初の候補時刻へ戻す。

確認のたびにOCRや翻訳を呼ぶ構成にはしていない。

翻訳は従来どおり確定区間ごとに最大1回である。

## 保存JSONからの動画再生

最初の実画面確認では、保存JSONを読み込んでも元動画が再生されなかった。

保存JSONの`source_video.path`と元動画の実在は確認できた。

画面側はこのパスへ`convertFileSrc`を適用していたが、JSON選択時のファイルダイアログが許可するのはJSONファイルだけだった。

そのため、JSON内の動画パスはTauriのasset protocol scopeへ追加されず、WebViewが動画を読み込めなかった。

保存JSONの読込処理で元動画の実在を確認し、その動画1ファイルだけをasset protocol scopeへ追加するよう修正した。

ホームディレクトリや動画フォルダー全体への許可拡大は行っていない。

元動画が移動または削除されている場合は、元の場所へ戻すよう日本語で通知する。

修正後、ユーザーが同じ保存JSONから元動画を開き、4:55付近まで再生位置を確認できた。

保存JSONから元動画を再生する修正は実画面で確認済みである。

## 4:55付近の追加確認

実画面確認中に、4:55付近でも字幕が表示されないという報告があった。

元映像では294.6秒から295.2秒に`아 이 자식 봐라?`、295.4秒から297.0秒に`아니 기 싸움 좀 하나?`を確認した。

最低表示時間1.2秒の修正後JSONでは、前者に対応する294.6秒から295.2秒の0.6秒区間が`shorter_than_minimum_duration`として破棄されていた。

後者は295.2秒から297.2秒の区間として保存され、OCR原文`아기싸하?`と日本語訳`幼いサハ？`が存在した。

最低表示時間だけを0秒へ変更した追加実測では、294.6秒から295.2秒も独立区間として保存された。

ただし、その区間のOCRは低信頼の`아이 지식 바라?`となり、翻訳対象には採用されなかった。

4:55.0時点の非表示は最低表示時間1.2秒による仕様どおりの除外であり、GOAT字幕と同じ誤統合ではない。

295.2秒以降も表示されない場合は、保存データではなく実画面の時刻同期または表示処理を追加調査する必要がある。

修正後の全11区間を最低表示時間だけで選別すると、1.2秒では6区間とOCR14回、0.8秒では7区間とOCR17回、0.6秒では10区間とOCR25回、0秒では11区間とOCR27回になる。

新しい詳細変化判定は200ms間隔の3フレーム継続を必要とするため、微妙な切替を含む字幕の実用上の下限は約0.6秒である。

0.6秒は4:55の短字幕を区間として残すが、この実測では採用可能なOCRと翻訳の件数は1.2秒条件と同じ2件だった。

この結果を受け、新規解析の初期値を0.6秒へ変更した。

保存済みJSONに記録された最低表示時間は変更せず、同じ条件で再解析できるようにする。

0.6秒への変更は短字幕の区間を残すためのものであり、低信頼OCRを翻訳可能にする変更ではない。

Ns8 600–660秒では、旧方式が連結していた630.4秒から634.8秒の3字幕を別区間として検出した。

集計上の過分割は3から4へ増えた。

増加した1件は、正解境界633.2秒に対して検出境界が633.0秒となり、0.2秒の重なりを前後両方へ数えた結果である。

この箇所の前後は正解データ上も別字幕であり、背景変化だけによる同文の分割ではない。

新指標による短い変化が2フレーム以内で戻る合成回帰テストでは、同じ区間を維持した。
