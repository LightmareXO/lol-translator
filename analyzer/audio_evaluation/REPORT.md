# LoL韓国語音声と画面字幕の対応検証

## 結論

今回の1構成では、音声認識をOCRや翻訳の自動補正へ使えるだけの安定性を確認できなかった。

既存動画の8区間では、7区間が同じ定型句に崩れ、残る1区間も画面字幕と異なる文を出力した。

一方、追加動画のt15では、白色行と同じ語幹を同じ時刻に認識できたため、音声が字幕候補の照合に役立つ可能性を確認した。

ただし、実行環境は音声ファイルを評価者モデルへ提示できなかったため、実音声による最終確認は未実施である。

字幕、OCR、ASRのどれかを正解とみなす推測を避け、確認済み件数は次のとおり0件とした。

| 分類 | 実音声で確認済み | 未確認候補 |
| --- | ---: | ---: |
| 発話とほぼ同じ字幕 | 0 | 1 |
| 発話の要約または言い換え | 0 | 0 |
| 読み上げない補足字幕 | 0 | 1 |

見つからなかった要約または言い換えを、他の失敗行から推測して分類していない。

## 既存資料と作業起点

リポジトリ直下に`AGENTS.md`は存在しなかった。

CodexのChatGPTプロジェクト用`AGENTS.md`は同期済み`source/`を読み取り専用とする指示だけを含み、今回のリポジトリには同期資料がなかった。

`README.md`、`analyzer/ocr_evaluation/REPORT.md`、`analyzer/ocr_evaluation/manifest.json`、関連コードを確認した。

OCR評価は`QK95uTvf7ks`の`g01_f02`から`g08_f02`までを使うため、今回も同じ動画IDと字幕IDを再利用した。

追加動画は翻訳評価ブランチの既存ID`Ns8VQexyJes`と`t15_annotation_f02`、`t15_speech_f02`を再利用した。

作業ブランチは`origin/main`から作成後、未マージの既存OCR成果物を取り込むため`origin/feat/8-ocr-evaluation`へfast-forwardした。

既存OCR成果物、翻訳評価ファイル、リポジトリ共通の依存定義は編集していない。

## 対象区間

既存OCR評価の8区間と、追加動画の6分10秒付近にある2行字幕1区間を対象にした。

画面字幕の表示区間は4fpsのコンタクトシートを目視し、0.25秒刻みで最後に全文を確認できたフレームまで記録した。

真の切替時刻には最大0.25秒の不確かさがある。

音声区間は各表示区間の前後2秒を含む。

動画ID、字幕ID、表示区間、音声区間の全対応は`manifest.json`と`results/correspondence.csv`に保存した。

t15は黄色行と白色行を別の字幕IDとして保持した。

| 字幕ID | 色と役割 | 表示区間 | 音声区間 | 字幕 |
| --- | --- | ---: | ---: | --- |
| `t15_annotation_f02` | 黄色、編集注釈 | 368.25–370.75 | 366.25–372.75 | `카이사 전적 검색 중` |
| `t15_speech_f02` | 白色、発話候補 | 369.25–370.50 | 366.25–372.75 | `탈론 하는 친구네` |

## 音声認識構成

Windows上で`faster-whisper 1.2.1`と`CTranslate2 4.8.2`を隔離venvへ導入した。

モデルは多言語の`large-v3-turbo`をCTranslate2形式へ変換した`mobiuslabsgmbh/faster-whisper-large-v3-turbo`、revision `0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf`である。

OpenAIのモデルカードは`large-v3-turbo`を809M parameterの多言語モデルとし、99言語を対象に掲げている。

同じ資料は、言語ごとの性能差、実在しない文の生成、反復が起こりうると明記している。

faster-whisperの公式READMEはCPUでの`int8`、単語時刻、VADの利用方法を示している。

今回はCPU `int8`、8スレッド、beam size 5、韓国語固定、単語時刻あり、VADなし、前文条件づけなしに固定した。

初期比較では`initial_prompt=None`とし、正解字幕、OCR出力、hotword、prefixを渡していない。

公式資料:

- [OpenAI Whisper large-v3-turbo model card](https://huggingface.co/openai/whisper-large-v3-turbo)
- [faster-whisper README](https://github.com/SYSTRAN/faster-whisper/blob/master/README.md)
- [faster-whisper transcription API](https://github.com/SYSTRAN/faster-whisper/blob/master/faster_whisper/transcribe.py)
- [OpenAI Whisper repository](https://github.com/openai/whisper)

- OS：Microsoft Windows 11 Home 10.0.26200、x64
- CPU：AMD Ryzen 7 9800X3D、8コア16論理プロセッサ
- メモリ：31.6GiB
- GPU：NVIDIA GeForce RTX 5080 16GiB（今回のASRでは未使用）
- Python：3.10.11、64bit
- FFmpeg：8.1.1
- 入力音声：9クリップ、合計63.75秒、字幕10行

初回のモデル取得と初期化は26.05秒、9クリップの推論合計は30.45秒、プロセス全体は56.50秒だった。

クリップ単位の推論中央値は2.75秒、推論合計を音声長で割ったreal-time factorは0.478だった。

初回初期化はネットワーク取得とモデル読込を分離していないため、キャッシュ済み起動時間として使えない。

モデルキャッシュは1,621,667,203 bytes（1,546.54MiB）、snapshotは1,621,665,983 bytes、重みは1,617,884,929 bytesだった。

venvは336,142,901 bytes（320.57MiB）だった。

Pythonプロセスと生存中の子プロセスを50ms間隔で測ったpeak RSSは1,813,381,120 bytes（1,729.38MiB）だった。

測定値の機械可読版は`results/run-metrics.json`に保存した。

## 生出力

ASR生出力は`results/transcripts.raw.json`に保存した。

各segmentとwordは切り出し音声内の時刻と元動画の時刻を別フィールドに持つ。

たとえばt15の`clip_start_seconds=3.000`は、音声区間の開始366.25秒を加えた`source_start_seconds=369.250`に対応する。

生出力の代表例は次のとおりである。

| 区間 | 元動画時刻付きASR |
| --- | --- |
| g01 | 13.110–15.350 `한 발씩 쌓아야 돼.` |
| g03 | 90.750–92.430 `아.. 멈추지 않는다`、以後`흠`を3回 |
| g04 | 127.750–132.990 `다음 영상에서 만나요.` |
| g08 | 417.500–424.520 `다음 영상에서 만나요.` |
| t15 | 368.030–369.210 `탈론이 문젠가?`、369.250–370.190 `탈론하는 친구야?` |

既存動画ではg02、g04からg08までの7区間が`다음 영상에서 만나요`または同じ文の感嘆符付きになった。

異なる時刻のLoL字幕7件で同じ定型句が反復されたため、字幕補正へ使える出力ではない。

ただし、音声を直接確認していないため、行別注記では「ASR誤りまたは判定不能」とし、聞こえた内容を推測して書き換えていない。

## t15の2行判定

白色行は表示開始369.25秒とASR開始369.25秒が一致し、`탈론 하는 친구`までが共通した。

しかし、字幕末尾は`네`、ASR末尾は`야?`で異なる。

実音声を聞けなかったため、この差をASR誤りと字幕の言い換えのどちらにも確定せず、発話とほぼ同じ字幕の未確認候補にした。

黄色行は既存資料で編集注釈とされ、同じ時間帯のASRに`카이사 전적 검색 중`は現れなかった。

しかし、ASRの欠落だけでは「読み上げていない」を証明できない。

したがって、黄色行は読み上げない補足字幕の未確認候補とし、確認済み件数へ入れていない。

## OCRと翻訳を補助できる条件

音声は、ASR区間が字幕表示区間と重なり、固有語を含む複数語が字幕と一致し、反復や無関係な定型句がない場合に候補生成へ使える。

t15の白色行は、同じ時刻に`탈론 하는 친구`を得られたため、この条件の例になる。

それでも、末尾の差を自動修正してよいとは判断できない。

翻訳担当が利用する場合は、一致した語幹と時刻を照合候補として扱い、実音声確認後にだけ確定する必要がある。

一方、同じ文が複数の無関係な区間で反復された場合、ASRをOCR補正へ使えない。

今回のg02とg04からg08が該当する。

ASR文が表示終了後に始まる場合も、字幕との時間差、次の発話、ASR時刻誤差を分離できないため、自動補正へ使えない。

## 補足字幕を壊す条件

字幕行の役割を無視してASRだけへ合わせると、読み上げない編集注釈を消すおそれがある。

t15の黄色行は`카이사 전적 검색 중`という検索状況を伝えるが、同時間帯のASRに対応文がない。

この行をASRへ合わせて削除すると、音声にはない編集者の補足情報を失う。

2行字幕は一つの発話文へ連結せず、色、役割、表示区間、字幕IDを行ごとに保持する必要がある。

## 未確認事項

全10行の実音声確認が未実施である。

とくにt15の白色行末`네`とASRの`야?`、黄色行が読み上げられていないこと、既存動画8区間でASRが落とした実際の発話を確認する必要がある。

`reviews.json`の`confirmation_status`を`confirmed_by_listening`へ変更し、分類と根拠を更新して対応表を再生成すれば、確認済み件数へ反映できる。

今回は翻訳とOCR自動補正を実装していない。

## 成果物

- `manifest.json`：動画ID、字幕ID、表示区間、音声区間、行の役割
- `extract_audio.py`：SHA-256検証付きの音声抽出
- `transcribe.py`：固定1構成の時刻付きローカルASRと資源測定
- `results/transcripts.raw.json`：字幕で修正していない生出力
- `reviews.json`：生出力と分離した事後注記と確認状態
- `build_correspondence.py`：翻訳担当向けJSONとCSVの生成
- `results/correspondence.json`、`results/correspondence.csv`：行単位の対応表
- `results/run-metrics.json`：時間、容量、メモリの実測値
- `requirements.txt`、`requirements-lock.txt`：担当ディレクトリだけで使う依存
- `test_core.py`：時刻、ID、集計の単体テスト
